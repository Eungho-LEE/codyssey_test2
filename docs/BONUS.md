# E1-2 보너스 과제

2026-11-10에 공식 원문의 보너스 5개 항목을 구현했다. Python 표준 라이브러리만 사용하며 기존 두 클래스 구조와 저장 파일 복구 기능을 유지한다.

| 요구사항 | 구현과 확인 |
| --- | --- |
| 랜덤 출제 | `random.sample(self.quizzes, count)`로 중복 없이 출제하며 원본 목록의 순서를 바꾸지 않는다. 매번 반드시 다른 순서가 나오는 것은 아니다. |
| 문제 수 선택 | 플레이 시작 시 1~등록 개수의 정수를 입력한다. 빈 목록은 입력을 요구하지 않는다. |
| 힌트와 점수 차감 | Quiz.hint, 등록 시 선택 입력, 풀이 중 `h`. 같은 문제의 반복 조회는 추가 차감하지 않는다. |
| 퀴즈 삭제 | 메뉴 6 → 번호 → `y` 확인 후 삭제하고 파일에 저장한다. 0 또는 확인 거부는 취소한다. |
| 점수 히스토리 | 메뉴 7에서 날짜·시간, 문제 수, 정답 수, 점수, 힌트 수를 본다. 모든 완료 판을 JSON에 저장한다. |

## 실행과 점수 정책

```bash
python3 main.py
```

메뉴 1에서 문제 수를 선택한다. 정답 번호는 1~4이며, 힌트는 `h`로 볼 수 있다. **정답당 10점, 힌트가 있는 문제에서 최초 조회 시 3점 차감, 최종 점수는 최소 0점**이다. 힌트를 보고 오답을 골라도 힌트 차감은 적용된다. 힌트가 없는 기존 문제는 안내만 하고 차감하지 않는다.

메뉴 4의 기존 `최고 정답 수`는 이전 파일과 호환되도록 유지했다. 힌트 차감 후 최고 점수는 새 게임 기록의 points 최댓값으로 따로 표시한다. 문제 수가 다른 판의 정답 수나 점수는 난이도를 보정한 지표가 아니므로 메뉴 7에서 문제 수와 함께 비교한다. Ctrl+C·EOF로 중단한 판은 기록하거나 최고점에 반영하지 않는다.

## 기존 저장 데이터 호환

기존 state.json에서 hint가 없으면 빈 문자열, history가 없으면 빈 목록으로 읽는다. 기존 문제·최고 정답 수는 보존한다. 과거에 저장되지 않았던 게임 날짜와 개별 기록은 복원하거나 만들어내지 않는다. 파일 구조 오류는 기존 방식대로 원본을 백업하고 복구한다. 저장 실패 시 메모리 변경과 파일 저장 실패를 구분해 안내한다.

새 기록 형식의 예시(설명용):

```json
{
  "quizzes": [{"question": "예시", "choices": ["A", "B", "C", "D"], "answer": 1, "hint": "첫 번째입니다."}],
  "best_score": 1,
  "history": [{"played_at": "2026-11-10T15:00:00+09:00", "question_count": 1, "correct": 1, "points": 7, "hints_used": 1}]
}
```

처음 실행한 기본 문제에는 힌트가 있다. 이전 state.json에 저장한 문제에는 힌트가 자동 추가되지 않는다. 새 문제를 등록하면서 힌트를 넣을 수 있다. state.json은 Git 제외 대상이며 실제 사용자의 저장 파일은 검증 중 수정하지 않았다.
